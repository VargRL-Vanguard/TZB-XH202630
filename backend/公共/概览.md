# 公共/ — 公共基础设施（无数据层） + **3 项硬指标计算器**

> 任何成员**可引用**、但**不得修改**。所有修改需 4 人评审后由成员 A 落地。
> **本项目参赛 XH-202630 挑战杯**。`公共/` 额外承担 **3 项硬指标计算器** + **A-05 端到端验收脚本** 的责任。

## 关键约定：数据库不在 公共/

`公共/` **不**提供 `db.py`。每个业务区**自管**自己的数据层（自己的 `db.py` / `config.py` / `models/`），原因：

- 数据库是各区私有数据，互不依赖，互不干涉
- A 改 `db.py` 不会影响 B/C/D；B 改库不会影响 A
- 各区可选用不同的存储方案（PostgreSQL / MySQL / SQLite / 内存 Mock）互不约束

## 谁来初始化

由 **成员 A** 在第一阶段创建并提交，之后由 A 维护。

## 3 项硬指标计算器（**夺奖核心**）

A 维护 `metrics.py`，**B / C / D 直接调，禁止重写**：

```python
from backend.公共 import metrics

# 幻觉率：< 0.05
hallucination_rate = metrics.calc_hallucination_rate(generated_text, ground_truth_chunks)

# 画像-难度适配准确率：≥ 0.85
match_accuracy = metrics.calc_match_accuracy(learner_profile, resource_difficulty)

# 核心知识点覆盖率：≥ 0.90
coverage = metrics.calc_coverage(generated_text, required_kps)
```

每个函数：
- 输入输出签名固定（见上）
- 至少 3 个单测（含边界值 0、1、空输入）
- 任何调用方**不得**自己实现校验函数

## A-05 端到端验收脚本（**夺奖最后一道关**）

A 维护 `quality_check.py`，**所有 Agent 任务完成后跑一次**：

```bash
python -m backend.公共.quality_check --profiles path/to/test_profiles --kb path/to/kb
```

输出报告 `quality_report_{ts}.json`，含 3 项指标实际值 + 是否达标，归档到 `docs/quality_reports/`。

**3 项硬指标必须同时达标**：
- 幻觉率 `< 0.05`
- 画像-难度适配准确率 `≥ 0.85`
- 核心知识点覆盖率 `≥ 0.90`

**未达标 → 阻塞提交，必须迭代到达标为止**。

## 文件清单

```
公共/
├── 概览.md
├── config.py            # 基础配置：PORT / LOG_LEVEL / ENV / JWT_SECRET / AGENT_TIMEOUT_SEC / QUALITY_THRESHOLD（**不含** DB_URL）
├── response.py          # 统一响应封装：{ code, message, data }
├── auth_middleware.py   # 解析 token → userId，供 B/C/D 路由使用
├── logger.py            # 日志封装
├── errors.py            # 自定义异常：BizError / AuthError / NotFoundError / AgentError / QualityError
├── metrics.py           # ⭐ 夺奖核心：3 项硬指标计算器
├── quality_check.py     # ⭐ 夺奖核心：A-05 端到端验收脚本
└── __init__.py          # 统一导出：B/C/D 可 `from backend.公共 import response, logger, errors, metrics`
```

## 使用约定

- B / C / D 通过 `from backend.公共.xxx import ...` 引用
- 不在本目录写业务逻辑；只放"4 个区都会用到"且**无状态**的东西
- **3 项指标函数** 是 B/C/D 的强制依赖，必须**只**从这里 import，不允许在自己区写同名函数
- 任何扩展（缓存、限流、消息队列客户端等）先在本目录评审通过再使用
