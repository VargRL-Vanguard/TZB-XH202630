# 后端分工说明

> 4 人并行开发，文件目录**物理隔离**，各自仅提交自己负责的目录，避免 Git 冲突。

## 分工总览

| 成员 | 负责目录 | 主要职责 | 涉及接口前缀 |
| --- | --- | --- | --- |
| **成员 A** | `backend/1_用户与聊天/`  | 用户认证、用户信息、聊天、消息、WebSocket 实时通道 | `/api/auth`、`/api/user`、`/api/chat`、`/ws` |
| **成员 B** | `backend/2_学情数据/`   | 学情画像、学习活动记录 | `/api/student`、`/api/activity` |
| **成员 C** | `backend/3_学习内容/`   | 学习路径、学习建议（不含 AI 生成部分） | `/api/learning-path`（除 ai-result）、`/api/suggestions`（除 ai-result） |
| **成员 D** | `backend/4_AI集成/`     | 3 个 AI 的统一适配层 | `/api/ai-chat`、`/api/learning-path/ai-result`、`/api/suggestions/ai-result` |

## 4 个区域 + 公共区

```
backend/
├── 公共/                # 仅放跨区通用工具：response / logger / errors / config（基础）/ auth_middleware
│                        # **不放数据库**，db 由各区自管
├── 1_用户与聊天/        # A：用户与基础聊天（地基，所有人依赖）
│   ├── db.py            # ← 本区自有 DB
│   └── config.py        # ← 本区自有配置（USER_CHAT_DB_URL）
├── 2_学情数据/          # B：学情数据
│   ├── db.py            # ← 本区自有 DB
│   └── config.py        # ← 本区自有配置（STUDENT_DATA_DB_URL）
├── 3_学习内容/          # C：学习内容（路径 / 建议 的非 AI 部分）
│   ├── db.py            # ← 本区自有 DB
│   └── config.py        # ← 本区自有配置（LEARNING_CONTENT_DB_URL）
└── 4_AI集成/            # D：AI 集成（接入 3 个 AI）
    ├── db.py            # ← 本区自有 DB
    └── config.py        # ← 本区自有配置（AI_INTEGRATION_DB_URL + 3 个 AI 的 key/endpoint）
```

## 关键约定：数据库由各区自管

- **每个区一个独立数据库**（`USER_CHAT_DB_URL` / `STUDENT_DATA_DB_URL` / `LEARNING_CONTENT_DB_URL` / `AI_INTEGRATION_DB_URL`），可选用不同的存储（PostgreSQL / MySQL / SQLite / 内存）
- 数据库连接 / ORM / 表结构全部在自己区目录内，**互不干涉**
- 跨区访问数据只能通过对方区暴露的模块级函数（A 暴露 `get_user_by_id`，B 暴露 `get_student_snapshot`，C 暴露 `save_ai_generated_*`），**禁止**直连对方数据库
- `公共/` 只放无状态的跨区工具（response / logger / errors / config 基础字段 / auth_middleware）

## 依赖关系

```
A (用户与聊天)  ◀── 所有人需要 userId / token
   ▲
   │ A 先开工；A 提交 A-00（自有 DB）+ A-01（认证）+ S-02（auth_middleware）后，B/C/D 启动
   │
   ├── B (学情数据)        ──► 提供学情数据 ──► D 拼装 prompt
   │
   ├── C (学习内容)        ──► 提供路径 / 建议存储 ──► D 写回
   │
   └── D (AI集成)          ◀── 依赖 A、B、C，最后接入 3 个 AI
```

## 启动与协作流程

1. **A 先开工**：
   - 完成 S-01（公共基础工具）
   - 完成 A-00（用户与聊天 自有 DB）+ A-01（认证）+ S-02（auth_middleware）
   - 提交后通知 B/C/D，B/C/D 即可开工各自的 B-00 / C-00 / D-00
2. **B / C / D 并行**：各自先完成自己的 00 任务（自有数据层），再做 01+ 业务任务
3. **D 最后接入 AI**：在 A、B、C 已有接口之上，封装 3 个 AI provider，完成 `/api/ai-chat/*`、`ai-result` 等
4. **每日同步**：4 人每天 commit 前**只动自己目录**；`公共/` 修改需 4 人评审

## 3 个 AI 接入位置（成员 D）

| AI 名称 | 用途 | 路由 | D 目录中的文件 |
| --- | --- | --- | --- |
| AI 辅导 | 主对话答疑 | `/api/ai-chat/send` | `4_AI集成/chat/send.py` + `4_AI集成/providers/chat_ai.py` |
| AI 路径生成 | 生成学习路径 | `/api/learning-path/ai-result` | `4_AI集成/path/ai_result.py` + `4_AI集成/providers/path_ai.py` |
| AI 建议生成 | 生成学习建议 | `/api/suggestions/ai-result` | `4_AI集成/suggest/ai_result.py` + `4_AI集成/providers/suggest_ai.py` |

3 个 provider 共享 `4_AI集成/providers/base.py` 抽象接口，新增 / 替换 AI 服务只改 `providers/` 目录。

## Git 提交规范

- 一个成员一个分支：`feat/A-用户与聊天`、`feat/B-学情数据`、`feat/C-学习内容`、`feat/D-AI集成`（**目录已用 1/2/3/4 编号：`1_用户与聊天/`、`2_学情数据/`、`3_学习内容/`、`4_AI集成/`**）
- 每次 PR **只**变更自己目录下的文件 +（必要时）`backend/概览.md` / `backend/任务总看板.md`
- 严禁跨区改文件；如需修改 `公共/`，单独提 PR 并 @ 全员

## 前端对接

前端无需改文件路径。`api-doc.js` 中已规定的所有路径保持不变，4 人按本分工各实现一段即可。
