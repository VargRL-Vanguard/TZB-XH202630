## 3 大 Agent 之审核裁判 Agent（D-06 ⭐） + 协同编排器（D-03 ⭐）

> **挑战杯 3 个核心 Agent 之一**（其他 2 个在 B-05 / C-04）。

**审核 Agent 职责**：把 C 生成内容**严格**与 B 知识库切片做比对 → 计算幻觉率 + 覆盖率 → 输出 0-1 评分。
**入口**：`backend.d_AI集成.audit.audit(studentId, content, kp_ids)`
**评分公式**：`score = 0.6 * (1 - hallucinationRate) + 0.4 * coverage`
**辩论机制**：当 `score < 0.85` 时，触发领域专家 vs 审核裁判的辩论，最多 2 轮。

**协同编排器职责**：串起 B 诊断 → C 生成 → D 审核 → 决策（pass / retry / 反馈降维）的"分析-生成-校验-决策"闭环。
**入口**：`backend.d_AI集成.orchestrator.orchestrate(studentId, resource_type)`
**事件**：所有 Agent 过程通过 A-04 `ws.emit` 推送 5 类事件 + 落 `agent_log` 表。

## 3 项硬指标责任

| 指标 | D 的贡献 |
| --- | --- |
| 幻觉率 | **D-06 审核 Agent** 把幻觉率降至 < 0.05；D-03 触发重试 |
| 覆盖率 | D-06 校验 C 生成内容覆盖率，< 0.90 触发重试 |

| SuggestAI | 学习建议生成 | `providers/suggest_ai.py` | 已有 |
| **EmbedAI** | **知识库 embedding 检索** | `providers/embed_ai.py` | **夺奖新增** |

4 个 provider **必须**实现 `providers/base.py` 里的统一接口：

```python
class BaseAIProvider(Protocol):
    name: str
    async def invoke(self, prompt: str, *, context: dict, **kwargs) -> str: ...
    async def stream(self, prompt: str, *, context: dict, **kwargs) -> AsyncIterator[str]: ...
    async def invoke_with_audit(self, prompt: str, *, context: dict, audit_callback=None) -> str: ...  # 夺奖新增
```

切换 / 新增 AI 服务（接 4 个 AI 时）只改 `providers/` 目录，业务路由不动。4 个 AI 的 key / endpoint 由本区 `config.py` 读取。
