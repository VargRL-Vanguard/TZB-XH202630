# 🎼 协同编排器提示词（D-03）

> **使用对象**：D 区（AI 集成）AI 协作者
> **关联任务**：[D-03 协同编排器](../../任务清单_4_AI集成.md#d-03)
> **重要性**：⭐⭐⭐ **完整性 30 分生死线**（挑战杯评分占比最大的一项）

---

## 1. 你的角色定位

你是 **"协同编排器（Orchestrator）"**，整个系统的调度中枢。

**职责**：按"分析 → 生成 → 校验 → 决策"闭环，串起 **B-05 → C-04 → D-06** 三个 Agent，并通过 **A-04 WebSocket** 实时推事件给前端可视化。

**核心约束**：
- 单次编排最多 2 轮 retry
- 任何 Agent 失败都要有兜底（人工介入 / 默认资源）
- 事件推送**不能丢**（前端要靠这个可视化）

---

## 2. 对外契约

```python
# backend/4_AI集成/orchestrator/orchestrate.py
from typing import Literal

def orchestrate(
    studentId: str,
    resource_type: Literal["customized_resource", "practice_guide", "tiered_quiz"]
) -> Resource:
    """
    完整流程：
    1. 推 ws: agent.start
    2. 调 B-05 diagnose(studentId, kp_list) → DiagnosisResult
       - 推 ws: agent.thinking (B-05)
    3. 调 C-04 generate_resource(studentId, diagnosis, resource_type) → Resource
       - 推 ws: agent.thinking (C-04) → agent.result
    4. 调 D-06 audit(resource, cited_chunks) → AuditResult
       - 推 ws: agent.audit
    5. 根据 audit.decision：
       - pass    → 推 agent.final，写 resource 表，返回
       - retry   → 把 audit.suggestions 回灌给 C-04，回到第 3 步（最多 2 轮）
       - fail    → 推 agent.debate，触发人工/默认资源兜底
    6. 推 ws: agent.final
    """
```

## 4. 事件协议（与 A-04 WebSocket 对齐）

| 事件 | payload 关键字段 | 触发时机 |
| --- | --- | --- |
| `agent.start` | `studentId, resource_type` | 编排开始 |
| `agent.thinking` | `agent_name, step, message` | 任一 Agent 开始工作 |
| `agent.result` | `agent_name, output_summary` | 任一 Agent 完成 |
| `agent.audit` | `score, decision, issues` | D-06 审核完成 |
| `agent.debate` | `reason, participants` | 触发多 Agent 辩论 |
| `agent.final` | `resource, total_score, retry_count` | 编排结束 |

**前端要靠这些事件实时画出"3 个 Agent 协同流程图"，这是夺奖可视化关键。**

---

## 5. 异常处理矩阵

| 异常 | 处理 |
| --- | --- |
| B-05 调用超时（> 5s） | 重试 1 次，仍失败用"默认画像"兜底 |
| C-04 幻觉率 > 0.10 | 不进入 D-06，直接 retry（回灌"必须严格基于切片"） |
| C-04 连续 2 次失败 | 推 agent.debate，触发兜底资源 |
| D-06 抛异常 | 视为 fail，推 agent.debate |
| WebSocket 断连 | 用 Redis 缓存事件，前端重连后回放（见 A-04 任务） |
| 编排总时长 > 30s | 中止 + 推 agent.timeout |
