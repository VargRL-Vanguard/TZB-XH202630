
### 2.2 统一响应格式（所有接口一致）

```json
{ "code": 200, "message": "success", "data": { } }
```

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 200 | 成功 | 取 `data` |
| 400 | 参数错误 | toast `message` |
| 401 | 未登录 / token 过期 | **清除本地 token → 跳登录页** |
| 403 | 无权限（如学生改别人画像） | toast `message` |
| 404 | 资源不存在 | toast `message` |
| 500 | 服务器内部错误 | 统一"服务异常，请稍后重试"，**不显示原文** |

### 2.3 认证方式

```
Header: Authorization: Bearer <token>
（WebSocket 用 query 参数：/ws?token=xxx）
token 有效期 24h，由 POST /api/auth/login 获取
```

## 5. 页面清单（P0 必须做，按此优先级开发）

### P0-1 登录 / 注册页
- 登录：用户名 + 密码；注册：用户名 / 密码 / 姓名 / 角色（student|teacher|admin 下拉）+ 可选 education、major
- 密码前端预校验：≥8 位 + 字母 + 数字（后端同样校验，双保险），校验失败按钮置灰 + 具体原因
- 登录成功存 token + userId + role → 按角色跳转（student → 学情仪表盘；teacher → 学生列表视角）
- **登录页也要有品牌感**：项目名 + 一句副标题（"领域知识个性化生成与多智能体协同决策系统"）+ 背景科技感插画/渐变（录屏第一个画面）
- 表单支持回车提交；登录按钮防抖（连点不发出多个请求）；错误提示在表单内联展示（不用 alert）

### P0-2 ⭐ 多 Agent 协同可视化大屏（**全项目最重要页面**）
- 触发：学生点击"为我生成个性化学习资源"
- 页面元素（最低要求）：
  - **3 张 Agent 卡片**横排：学情诊断 Agent（B-05）→ 领域专家 Agent（C-04）→ 审核裁判 Agent（D-06），箭头连接表现流水线
  - 每张卡片状态机：`空闲 → 工作(转圈/呼吸灯) → 完成(✓) → 辩论中(⚡)`，由 WS 事件驱动（见 §6）
  - **思考过程流式气泡**：`agent.thinking` 事件的 `content` 打字机效果逐条追加（评审最吃这个）
  - **辩论对决视图**：`agent.debate` 事件触发时，展示参与 Agent 的观点对撞（左右分栏或对话气泡）
  - 顶部 traceId + 步骤进度条（1/4 → 4/4）
  - `agent.final` 事件：关闭所有 loading，弹出最终资源结果卡
- 设计基调：深色科技感（背景 `#0B1020`）/ 蓝→紫渐变主视觉 / 连线粒子流动画。**这是演示视频的主菜，值得花 50% 的前端工时**
- 额外硬要求：
  - 事件时间轴侧栏：本次 trace 的全部事件按时间排列，可点击回看（评审问"刚才那步做了什么"直接点）
  - **事件回放模式**：提供"重播"按钮，把本次 trace 的事件序列按原始间隔重放（演示视频可补拍镜头 + 现场可二次展示）

## 6. WebSocket 协议（⭐ 逐字段，直接决定 P0-2 实现）

### 6.1 连接与保活

```js
const ws = new WebSocket(`ws://127.0.0.1:8000/ws?token=${token}`);
// 每 30 秒发心跳，否则 60 秒后被服务端清理：
ws.send(JSON.stringify({ type: "ping", timestamp: Date.now()/1000 }));
// 收到 {type:"pong"} 为正常；断线必须自动重连（指数退避 1s/2s/4s...最大 30s）
```

### 6.2 客户端可发消息（4 种）

```json
{ "type": "ping", "timestamp": 1786783773 }
{ "type": "subscribe",   "channel": "agent:学情诊断Agent" }
{ "type": "unsubscribe", "channel": "agent:学情诊断Agent" }
{ "type": "chat", "targetId": "u002", "content": "你好" }
```

### 6.3 服务端 5 类 Agent 协同事件（夺奖核心，UI 状态机照此写）

事件流典型顺序：
```
agent.start → agent.thinking ×N → agent.result → agent.debate(可选) → agent.final
```

| 事件 | 字段 | 前端 UI 行为（硬性要求） |
| --- | --- | --- |
| `agent.start` | `agentName, step, traceId, timestamp` | 对应 Agent 卡片 → "工作中"状态（转圈/呼吸灯）；进度条跳到 step |
| `agent.thinking` | `agentName, step, content, traceId, timestamp` | **打字机流式追加**到该卡片的思考气泡区（不是一次性替换） |
| `agent.result` | `agentName, step, content, data, traceId, timestamp` | 卡片 → "完成 ✅"；`data` 是结构化结果，暂存待 final 展示 |
| `agent.debate` | `agents[], topic, content, traceId, timestamp` | 辩论模式：参与 Agent 卡片之间出现 ⚡ 连线，topic 打在中间，观点气泡交替 |
| `agent.final` | `ok, summary, traceId, timestamp` | 全部卡片收尾；关闭 loading；`ok=true` 弹资源结果卡，`ok=false` 显示错误 + 重试按钮 |

其他服务端推送：`{type:"message", from, content, timestamp}` 新聊天消息、`{type:"notification", ...}` 系统通知、`{type:"pong"}`、`{type:"error", message}`。

### 6.4 前端状态机参考

```
idle --agent.start--> running --agent.thinking×N--> running
running --agent.result--> done
done --agent.debate--> debating --agent.debate--> debating
any --agent.final--> finished(ok: bool)
```

### 6.5 WS 工程硬要求

- 事件先写入 store（带 traceId 分组）再驱动 UI，**回放器直接读 store**，不重放网络
- 收到未知 `type` 的事件不许报错（容错记录到 console.debug，向后兼容 D 区加事件）
- 同一 traceId 的乱序事件（thinking 比 start 晚到等）要能容错渲染，不许白屏
- WS 断开时：页面顶部出现"实时连接已断开，正在重连…"黄色横幅；重连成功自动消失并补拉一次 `/api/visualization/*`（未上线前跳过）

## 7. 动画与交互规范

| --- | --- | --- |
| thinking 打字机 | 30-50ms/字 | 太快没有"思考感"，太慢拖节奏 |
| 状态切换（卡片/按钮） | 200-300ms `ease-out` | 超过 400ms 显得卡 |
| 数字滚动（指标卡） | 800ms，`ease-out` | 仪表盘进场统一节奏 |
| 辩论连线粒子 | 持续流动，粒子 20-40 个 | 方向 = 观点往复（A→B / B→A 交替） |
| 页面切换 | ≤ 200ms 淡入 | 不要花哨转场（录屏显乱） |
| 骨架屏 | 呼吸 1.5s 循环 | 数据未到时必须有，不许白块 |
- 动画期间帧率 **≥ 50fps**（用 Chrome DevTools Performance 面板自查，掉帧的动画宁可简化）
- `prefers-reduced-motion` 用户设置下自动降级为无动画版本（加分项）
- **思考/辩论气泡最多保留 50 条**，超出滚动的销毁，防长会话内存膨胀

---

## 8. 边界与异常态全覆盖（每页逐条自查）

每个数据页面必须实现 4 态，缺一就是"半成品观感"：

| 态 | 要求 |
| --- | --- |
| 加载态 | 骨架屏（结构相似），不许 spinner 空转超过 3s；3s 以上显示"加载较慢"文案 |
| 错误态 | 插画 + 一句话原因 + **重试按钮**；绝不显示堆栈 / code 原文 |
| 空态 | 插画 + 引导文案 + 行动按钮（如"还没有学习记录，去生成你的第一条路径 →"） |
| 断网/后端挂 | 全局横幅"服务暂不可用"；已缓存数据照常展示 |

其他硬性边界：
- 聊天发送失败：消息气泡变红 + 重发按钮，**不许消息凭空消失**
- 表单提交必须防重复（按钮 loading + 禁用）
- 分页到末页 / 列表为空 / token 半路过期（WS 收 error、HTTP 收 401 双通道都要处理）
- 路由直接输 URL 访问不存在页面 → 友好 404 页（带"返回首页"）

## 9. 性能与安全硬指标

### 性能（构建后实测，达不了标就优化）
- 首屏（登录页）可交互 < 2s（本机 nginx 静态托管下）
- 首屏 JS gzip ≤ 500KB：路由全部懒加载 + ECharts **按需引入**（`echarts/core`）+ UI 库按需引入
- 大屏动画期间 ≥ 50fps、内存无持续增长（连跑 10 次 trace 回放对比）
- 图片资源：除插画外不引大图；插画压缩到 ≤ 100KB/张

### 安全
- AI 生成内容渲染：**禁用 `v-html`/`dangerouslySetInnerHTML` 直插**；必须先 sanitize（DOMPurify），否则 XSS 评审现场翻车
- token 存储统一封装（建议内存 + sessionStorage），**不许**出现在 URL / console.log / 埋点里
- 生产构建关闭 sourcemap（`build.sourcemap: false`）
- 不引入任何需要外网 CDN 的运行时依赖（演示现场可能无外网，**全部资源本地打包**）
