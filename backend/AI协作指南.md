# AI 协作者工作指南

> 任何 AI 编程助手（Claude / Cursor / Trae / …）开始为本项目后端写代码前，**必须**完整读完本文件。
> 阅读完后，按 [§6 工作循环](#6-工作循环) 执行。
> **本项目参赛 XH-202630 挑战杯，目标擂主（12 万）**。**3 项硬指标红线**对 AI 同样适用。

## 1. 适用场景

- 团队成员用 AI 辅助生成某个任务下的代码
- 团队成员直接把整段任务交由 AI 自动完成
- AI 主动在 `git pull` 后扫描未完成任务并自行开工

无论哪种情况，AI 都必须**遵守协议**（[协作协议.md](./协作协议.md)）。

## 2. 必读文档清单（按顺序）

1. [`协作协议.md`](./协作协议.md) — 工作协议、**夺奖红线**、3 项硬指标
2. [`概览.md`](./概览.md) — 分工总览、**夺奖重点**、时间线
3. **根目录中自己专属的** `任务清单_N_xxx.md`（每人只读自己那一个文件即可），例如 `任务清单_a_用户与聊天.md`
4. **自己区的** `概览.md`（如 `b_学情数据/概览.md`）— 详细对外契约
5. `api-doc.js`（项目根目录）— 接口契约
6. **`backend/prompts/` 提示词库**（[`prompts/README.md`](./prompts/README.md)）— **做什么**
7. **`backend/workflows/` 工作流程库**（[`workflows/README.md`](./workflows/README.md)）— **怎么做（防 AI 幻觉关键）**

**禁止跳过**。任何一个文档里都可能存在影响代码正确性的约束。

## 3. 3 项硬指标红线（**AI 必须牢记**）

> **每一次写涉及 Agent / 知识库 / 资源生成的代码前，先确认指标会达标**。

| 指标 | 目标值 | AI 必须做的事 |
| --- | --- | --- |
| 幻觉率 | **< 0.05** | 内容生成**必须**基于 B 的 `list_kb_chunks_by_kp` 检索结果，**不得**让 provider 自由发挥；生成后调 `calc_hallucination_rate` 自检 |
| 画像-难度适配准确率 | **≥ 0.85** | 资源难度**必须**根据 `learnerProfile.weakKPs` 动态调整（1-5 档），生成后调 `calc_match_accuracy` 自检 |
| 核心知识点覆盖率 | **≥ 0.90** | 生成的资源**必须**显式覆盖 `weakKPs` 中的 ≥ 90% 知识点，生成后调 `calc_coverage` 自检 |

**指标函数唯一来源**：`backend.公共.metrics`（A 维护，禁止 AI 自己重写）。

## 4. 多智能体协作模式（**AI 必识别**）

项目核心是 **3 Agent 协同闭环**，AI 在写代码时必须严格区分自己的 Agent 身份：

```
B-05 学情诊断 Agent ─┐
                    ├─→ D-03 协同编排器 ─→ C-04 领域专家 Agent ─→ D-06 审核裁判 Agent ─→ 决策
A-04 WebSocket 事件 ─┘                                          │
                    └──────────── audit.score < 0.85 时触发辩论 ─┘
```

### 4.1 每个 Agent 的硬要求
- ✅ 通过 A-04 的 `ws.emit(agentName, event_type, ...)` 推送过程事件
- ✅ 落 `agent_log` 表（`backend.d_AI集成` 的 D-00 提供 ORM，**不**能直接写库）
- ✅ 调 A 的 `公共/metrics.*` 自检
- ✅ 保留 traceId，串联到下一个 Agent

### 4.2 5 类事件类型（必须全部支持）
| type | 触发时机 | payload |
| --- | --- | --- |
| `agent.start` | Agent 启动时 | `{agentName, step, traceId, ts}` |
| `agent.thinking` | Agent 处理中（可多次） | `{agentName, step, content, traceId, ts}` |
| `agent.result` | Agent 完成时 | `{agentName, step, content, traceId, ts}` |
| `agent.debate` | 审核不达标触发辩论时 | `{agents[], topic, traceId, ts}` |
| `agent.final` | 整个协同流程结束 | `{ok, traceId, ts}` |

## 6. AI 必须遵守的硬约束

| 类别 | 规则 |
| --- | --- |
| 文件 | **只**写自己区目录 + 根目录中自己专属的 `任务清单_N_xxx.md`；例外：`公共/` 仅 A 可写 |
| 数据库 | **只**在自己区新建 `db.py` / `config.py` / `models/`；**禁止**直连他人数据库 |
| 状态 | 开始前把 `⬜` 改为 `🟡` 并补 `**Owner**` / `**Started**`；完成时改为 `✅` 并勾选验收 |
| 契约 | 字段名 / 类型 / 路径以 `api-doc.js` 为准；如需变更，按 [协作协议 §5](./协作协议.md#5-接口契约管理) 走 |
| 依赖 | 任务标记 `依赖: A-03`，则 A-03 必须是 `✅` 状态才可开始；否则标 `🔒 阻塞` |
| 00 任务 | 每个区的第一个任务（`A-00` / `B-00` / `C-00` / `D-00`）是本区数据层地基，**必须**先做 |
| 测试 | 验收标准中包含 "测试" 的，AI 必须**真写**测试代码，不是注释 |
| 输出 | 不要修改 `任务清单_N_xxx.md` 之外的顶层文档（概览.md / 协作协议.md / AI协作指南.md） |
| **指标** | **只** `from backend.公共 import metrics`，**禁止**自己写同名函数 |
| **事件** | **只** `from backend.a_用户与聊天.ws.emit import emit`，**禁止**绕过 WebSocket 直接落库 |
| **日志** | 落 `agent_log` 表用 D 暴露的函数，**禁止**直接 INSERT |

## 7. 工作循环

```
1. git pull
2. 打开 根目录/任务清单_N_xxx.md（自己那一份）+ 自己区/概览.md
3. 找第一个 🟡（继续）或 ⬜（新开）的 ⭐ 夺奖专项 / P0 任务
4. 检查"依赖"列：依赖项是否全部 ✅？否 → 标 🔒 阻塞并停止
5. 把当前任务改为 🟡，补 Owner / Started
6. 按"涉及文件"创建 / 修改文件
   ↓
   ★ 涉及 Agent 任务：先确认 3 项硬指标怎么自检（用 metrics.*）
   ★ 涉及事件推送：用 ws.emit，**不**直接调 A 的 ws.send
7. 按"验收标准"自检
   ↓
   ★ 夺奖专项：额外跑 A-05 quality_check.py 确认指标
8. 把任务改为 ✅，勾选验收
9. git add 自己区目录 + 任务清单_N_xxx.md
10. git commit -m "<任务ID> <简述>"
11. 通知队友 / 提 PR
```

## 8. 跨区调用

AI 在自己区中需要使用其他区数据时，**只能**：

1. 引用 `公共/` 中由 A 维护的公共接口（含 `metrics.*`）
2. 调用对方区 `任务清单_N_xxx.md` / `概览.md` 中明确暴露的模块级函数

**禁止**：

- 直接 import 对方私有模块（如 `from backend.学情数据.models import ...` 需先在 B 的概览中声明可被引用）
- 直接读写对方数据表 / ORM
- 复制对方代码到自己区
- 在自己区新建对方区已经存在的表 / ORM
- **绕过 `ws.emit` 直接操作 WebSocket 推送**（破坏可视化完整性）

## 10. 出错处理

| 现象 | 怎么做 |
| --- | --- |
| 依赖的任务未完成 | 把当前任务标 🔒，在群里喊对应负责人 |
| `api-doc.js` 与需求矛盾 | 暂停，在群里提一个问题；不擅自改契约 |
| 发现其他区有 bug | 在群里反馈，**不要**直接改 |
| `公共/` 缺少必要工具 | 在群里提需求，让 A 加；AI 不要自己造 |
| 需要访问他人数据库 | 走对方暴露的模块级函数；如果还没暴露，群里提需求让对方加 |
| **3 项硬指标自检不通过** | **立即**停止写后续代码，先迭代知识库（找 B）或迭代 prompt（找对应 Agent 负责人） |
| **WebSocket 事件未推送** | 检查是否调 `ws.emit`，**不要**直接操作 ws |
| **agent_log 落库失败** | 检查是否调 D 暴露的写入函数，**不要**直接 INSERT |

### 12.4 工作流程 vs 提示词 的边界

| 维度 | 提示词库 | 工作流程库 |
| --- | --- | --- |
| **作用** | 告诉 AI **做什么** | 告诉 AI **怎么做** |
| **风格** | 描述性（"你是 XXX Agent，输出 YYY"） | 步骤式（"步骤 1：xxx；步骤 2：xxx"） |
| **每步内容** | 输入 / 输出 / 红线 | 输入 / 操作 / 输出 / 验证 / 失败处理 |
| **粒度** | 任务级 | 步骤级 |
| **防幻觉机制** | 锁定 Agent 角色 | 锁定每一步操作 |
