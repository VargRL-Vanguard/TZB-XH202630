# AI 协作者工作指南

> 任何 AI 编程助手（Claude / Cursor / Trae / …）开始为本项目后端写代码前，**必须**完整读完本文件。
> 阅读完后，按 [§5 工作循环](#5-工作循环) 执行。

## 1. 适用场景

- 团队成员用 AI 辅助生成某个任务下的代码
- 团队成员直接把整段任务交由 AI 自动完成
- AI 主动在 `git pull` 后扫描未完成任务并自行开工

无论哪种情况，AI 都必须**遵守协议**（[协作协议.md](./协作协议.md)）。

## 2. 必读文档清单（按顺序）

1. [`协作协议.md`](./协作协议.md) — 工作协议、ID 规则、状态机
2. [`概览.md`](./概览.md) — 分工总览、依赖关系、数据库归属
3. **根目录中自己专属的** `任务清单_N_xxx.md`（每人只读自己那一个文件即可），例如 `任务清单_1_用户与聊天.md`
4. `api-doc.js`（项目根目录）— 接口契约

**禁止跳过**。任何一个文档里都可能存在影响代码正确性的约束。

## 3. 任务文档结构（AI 必识别）

每个 `任务清单_N_xxx.md` 中的任务遵循统一模板，AI 应严格按字段执行：

```markdown
# 任务 N：[标题]   ← N 是该任务在本任务清单中的顺序号（1, 2, 3 …）

**ID**：[Area]-[Number]
**负责人**：[A / B / C / D / 公共]
**状态**：⬜ 待开始 / 🟡 进行中 / ✅ 完成 / 🔒 阻塞
**依赖**：[Task IDs 或 "无"]
**优先级**：P0 / P1 / P2
**Owner**: @姓名（仅在认领后填写）
**Started**: YYYY-MM-DD（仅在认领后填写）

## 涉及文件
- 相对路径（相对 backend/）

## 描述
一段话讲清楚要做什么

## 验收标准
- [ ] 验收点 1
- [ ] 验收点 2

## 接口契约
（如适用，贴 api-doc.js 中的对应条目）
```

## 4. AI 必须遵守的硬约束

| 类别 | 规则 |
| --- | --- |
| 文件 | **只**写自己区目录 + 根目录中自己专属的 `任务清单_N_xxx.md`；例外：`公共/` 仅 A 可写 |
| 数据库 | **只**在自己区新建 `db.py` / `config.py` / `models/`；**禁止**直连他人数据库 |
| 状态 | 开始前把 `⬜` 改为 `🟡` 并补 `**Owner**` / `**Started**`；完成时改为 `✅` 并勾选验收 |
| 契约 | 字段名 / 类型 / 路径以 `api-doc.js` 为准；如需变更，按 [协作协议 §5](./协作协议.md#5-接口契约管理) 走 |
| 依赖 | 任务标记 `依赖: A-03`，则 A-03 必须是 `✅` 状态才可开始；否则标 `🔒 阻塞` |
| 00 任务 | 每个区的第一个任务（`A-00` / `B-00` / `C-00` / `D-00`）是本区数据层地基，**必须**先做 |
| 测试 | 验收标准中包含 "测试" 的，AI 必须**真写**测试代码，不是注释 |
| 输出 | 不要修改 `任务清单_N_xxx.md` 之外的顶层文档（概览.md / 协作协议.md / AI协作指南.md） |

## 5. 工作循环

```
1. git pull
2. 打开 根目录/任务清单_N_xxx.md（自己那一份）
3. 找第一个 🟡（继续）或 ⬜（新开）的任务
4. 检查"依赖"列：依赖项是否全部 ✅？否 → 标 🔒 阻塞并停止
5. 把当前任务改为 🟡，补 Owner / Started
6. 按"涉及文件"创建 / 修改文件
7. 按"验收标准"自检
8. 把任务改为 ✅，勾选验收
9. git add 自己区目录 + 任务清单_N_xxx.md
10. git commit -m "<任务ID> <简述>"
11. 通知队友 / 提 PR
```

## 6. 跨区调用

AI 在自己区中需要使用其他区数据时，**只能**：

1. 引用 `公共/` 中由 A 维护的公共接口
2. 调用对方区 `任务清单_N_xxx.md` / `概览.md` 中明确暴露的模块级函数

**禁止**：

- 直接 import 对方私有模块（如 `from backend.学情数据.models import ...` 需先在 B 的概览中声明可被引用）
- 直接读写对方数据表 / ORM
- 复制对方代码到自己区
- 在自己区新建对方区已经存在的表 / ORM

## 7. Prompt 模板（推荐人 + AI 共用）

直接复制这段发给你的 AI 助手：

```
你是本项目后端开发的 AI 协作者。在写任何代码前，请依次完整阅读：
1. backend/协作协议.md
2. backend/AI协作指南.md
3. backend/概览.md
4. backend/任务清单_N_xxx.md（你负责的那个 N，只读自己那一份）
5. 项目根目录的 api-doc.js

你的工作范围：backend/<N_xxx>/ 下的所有文件 + 根目录的 任务清单_N_xxx.md。
不要修改其他区或顶层文档。

特别提醒：
- 数据库由各区自管，你只能在自己区创建 db.py / config.py / models/
- 不要直连他人数据库，只能调用对方暴露的模块级函数
- 如果是 <你的区> 的第一个任务（<你的区>-00），那是本区数据层地基，必须先做

当前任务：请认领并完成 <区>-<编号>（标题），按"工作循环 §5"执行，
完成后把状态改为 ✅，并在群内汇报。
```

## 8. 出错处理

| 现象 | 怎么做 |
| --- | --- |
| 依赖的任务未完成 | 把当前任务标 🔒，在群里喊对应负责人 |
| `api-doc.js` 与需求矛盾 | 暂停，在群里提一个问题；不擅自改契约 |
| 发现其他区有 bug | 在群里反馈，**不要**直接改 |
| `公共/` 缺少必要工具 | 在群里提需求，让 A 加；AI 不要自己造 |
| 需要访问他人数据库 | 走对方暴露的模块级函数；如果还没暴露，群里提需求让对方加 |
