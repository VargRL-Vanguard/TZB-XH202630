# 工作流程 11：演示视频流程（**D-09 专用**）

> 演示视频是评委**唯一会看的东西**，必须**严格按本流程**制作，**防止 AI 在视频脚本上产生幻觉**。

---

## 前置条件

- D-03 协同编排器已跑通
- A-05 quality_check 3 项硬指标全过
- A-04 WebSocket 实时事件可被前端看到
- B-07 3 组测试画像可用
- 演示账号：profile_003_企业转岗（最有故事性）

---

## 步骤 1：写视频脚本（严格按时间线）

**输入**：[`prompts/31_演示视频脚本_提示词.md`](../prompts/31_演示视频脚本_提示词.md) 第 3 节时间线

**操作**：照搬时间线，**不要改**

| 段 | 时长 | 内容 | 必做事项 |
| --- | --- | --- | --- |
| 1 | 0:00-0:30 | 开场 | 项目背景 + 痛点 |
| 2 | 0:30-1:30 | 架构总览 | 3 Agent + 协同流程图 |
| 3 | 1:30-7:00 | **演示场景** | profile_003 完整流程 |
| 4 | 7:00-8:30 | 3 项硬指标 | quality_report 表格 |
| 5 | 8:30-9:30 | 技术创新 | 动态迭代 + 多 Agent 辩论 |
| 6 | 9:30-10:00 | 结尾 | 总结 + 致谢 |

**总时长 ≤ 10 分钟**（硬性要求）

**输出**：1 份脚本（含旁白、画面、镜头）

**验证**：
- [ ] 每段时间加起来 = 10 分钟
- [ ] 第 3 段（演示场景）占了 5.5 分钟（**最大**）

**失败处理**：超时 → 砍第 5 段（技术创新）时长

---

## 步骤 2：准备演示数据

**输入**：profile_003_企业转岗.json

**操作**：
1. 加载 B-07 profile_003
2. 确认 studentId / name / background 字段
3. 准备 1 套**干净的知识库**（避免演示时跑出意外内容）

**输出**：1 套演示数据

**验证**：
- [ ] profile_003 能被 A-05 加载
- [ ] 配套的知识库 ≥ 90% 覆盖率

**失败处理**：profile 跑不通 → 改用 profile_001（最简单的）

---

## 步骤 3：录制素材（OBS Studio）

**输入**：脚本 + 演示数据

**操作**：
1. 装 OBS Studio（免费）
2. 配置录屏：1080p / 30fps / 麦克风
3. 准备浏览器：清缓存、关通知、调字号
4. **分段录制**（不要一镜到底）：
   - 录 0:00-1:30（开场 + 架构）
   - 录 1:30-7:00（演示场景，**重点**）
   - 录 7:00-10:00（指标 + 创新 + 结尾）
5. 每个段落录 2-3 遍，挑最好的

**输出**：3 段原始素材（mp4）

**验证**：
- [ ] 每段不超过 7 分钟（避免大文件）
- [ ] 麦克风清晰无杂音

**详细提示**：[`prompts/31_演示视频脚本_提示词.md`](../prompts/31_演示视频脚本_提示词.md) 第 4 节

**失败处理**：录坏了 → 重录（素材是基础，不要凑合）

---

## 步骤 4：剪辑初版（剪映 / Premiere）

**输入**：3 段原始素材

**操作**：
1. 打开剪映（新手友好）或 Premiere（专业）
2. 切掉每段的错误 / 重复 / 口误
3. 加字幕（旁白文字化）
4. 加背景音乐（轻音乐，不要太大声）
5. 转场用简单的 fade（**不要**花哨的）

**输出**：1 个初剪版本（5-7 分钟）

**验证**：
- [ ] 整体节奏流畅
- [ ] 字幕完整、无错别字
- [ ] 背景音乐不抢人声

**失败处理**：太长 → 砍技术细节，保留演示 + 指标

---

## 步骤 5：加"3 项硬指标"展示

**输入**：quality_report.md

**操作**：
1. 切到 `docs/quality_reports/quality_report_20260822_xxx.md`
2. 用录屏或截屏特写表格
3. 旁白念出 3 个数值（强调"全过"）

**输出**：1 段"指标展示"片段（1.5 分钟）

**验证**：
- [ ] 表格清晰可见
- [ ] 旁白念出准确数值

**详细脚本**：[`prompts/31_演示视频脚本_提示词.md`](../prompts/31_演示视频脚本_提示词.md) 第 5 节

**失败处理**：指标不达标 → **不录这一段**，先回去达标

---

## 步骤 6：加"技术创新"展示

**输入**：D-03 + C-06 跑通的截图

**操作**：
1. 录 1 个"动态迭代"案例（学生答错 → 系统自动降维）
2. 录 1 个"多 Agent 辩论"案例（audit score < 0.70 → 触发 debate）
3. 每个案例 30 秒

**输出**：1 段"技术创新"片段（1 分钟）

**验证**：
- [ ] 动态迭代有前后对比
- [ ] 辩论有 chat-like 展示

**详细脚本**：[`prompts/31_演示视频脚本_提示词.md`](../prompts/31_演示视频脚本_提示词.md) 第 6 节

**失败处理**：案例跑不出来 → 简化展示，**不要**造假

---

## 步骤 7：终剪 + 终版

**输入**：所有片段

**操作**：
1. 拼接到 ≤ 10 分钟
2. 加片头 / 片尾（队名 / 项目名 / 时间）
3. 输出 1080p / mp4 / h264
4. 文件名：`XH202630_领域知识个性化生成与多智能体协同决策系统_演示视频.mp4`

**输出**：1 个 ≤ 10 分钟的终版视频

**验证**：
- [ ] 时长 ≤ 10:00
- [ ] 1080p 清晰
- [ ] 文件 < 500MB（上传友好）

**失败处理**：超时 → 再砍技术细节

---

## 步骤 8：写 PPT（≤ 15 页）

**输入**：脚本 + 架构图

**操作**：按 [`prompts/31_演示视频脚本_提示词.md`](../prompts/31_演示视频脚本_提示词.md) 第 7 节

| 顺序 | 页面 | 内容 |
| --- | --- | --- |
| 1 | 封面 | 队名 / 项目名 / 学校 / 时间 |
| 2 | 项目背景 | 痛点 + 市场规模（1 张图） |
| 3 | 架构总览 | 3 Agent + 协同流程图 |
| 4-5 | 演示场景 | profile_003 截图 + 文字 |
| 6 | 3 项硬指标 | 表格 |
| 7 | 技术创新 | 动态迭代 + 多 Agent 辩论 |
| 8 | 总结 | 优势 + 未来工作 |
| 9-15 | 附录 | 团队 / 技术栈 / 参考 |

**输出**：1 个 ≤ 15 页的 PPT

**验证**：
- [ ] 张数 ≤ 15
- [ ] 每页 ≤ 30 字（**不要**长 PPT）
- [ ] 配色统一

**详细提示**：[`prompts/31_演示视频脚本_提示词.md`](../prompts/31_演示视频脚本_提示词.md) 第 7 节

**失败处理**：超 15 页 → 砍附录

---

## 步骤 9：内部审核

**输入**：终版视频 + PPT

**操作**：
1. 4 人 + 指导老师各看 1 遍
2. 收集反馈（按时长 / 内容 / 节奏）
3. 改一轮（如果时间允许）

**输出**：1 份内部审核记录

**验证**：
- [ ] 至少 3 人看过
- [ ] 反馈已记录

**失败处理**：反馈太多 → 9-1 前完成改，**不要**拖到最后

---

## 步骤 10：提交（9-5 前）

**输入**：终版视频 + PPT + 报告

**操作**：
1. 上传视频到 B 站 / 优酷（**不要**只放本地）
2. 准备 README（含视频链接 + GitHub 链接）
3. 队长统一提交

**输出**：1 份提交包

**验证**：
- [ ] 视频可在线播放
- [ ] 9-5 前提交
- [ ] 队长已确认

**详细提示**：[`prompts/31_演示视频脚本_提示词.md`](../prompts/31_演示视频脚本_提示词.md)
