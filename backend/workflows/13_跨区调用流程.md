# 工作流程 13：跨区调用流程（**B / C / D 跨区数据访问专用**）

> 跨区调用是**最容易踩坑**的地方，**禁止**直连他人数据库。
> 本流程定义"应该怎么做"和"绝对不能怎么做"。

---

## 核心原则

> **跨区数据访问 = 通过对方暴露的函数调用**
> **禁止** import 对方私有模块 / 直连对方数据库 / 复制对方代码

---

## 步骤 1：识别"是否真的需要跨区"

**输入**：当前任务

**操作**：先问自己：
1. 我需要的这个数据，**我的区**里有没有？
2. 如果没有，是不是该加到我自己的区（**不要**伸手去别人的区）？
3. 如果必须用别人的，**对方区的概览.md**里是否声明了对外函数？

**输出**：明确"需要跨区"或"不用跨区"

**验证**：
- [ ] **不**需要跨区 → 改用本区数据
- [ ] 需要跨区 → 对方区有声明的对外函数

**失败处理**：对方没声明 → 群里提需求让对方加，**不要**自己加

---

## 步骤 2：找到对方区的对外函数

**输入**：对方区目录 + 概览

**操作**：
1. 打开 `backend/<对方区>/概览.md`
2. 找"对外契约"或"暴露的函数"小节
3. 找到你需要的函数 + 字段名 + 类型

**已声明的对外函数清单**：

| 函数 | 提供方 | 调用方 | 用途 |
| --- | --- | --- | --- |
| `get_user_by_id(userId)` | A | B / C / D | 拿用户基本信息 |
| `verify_token(token)` | A | B / C / D | 校验 token |
| `get_user_profile(userId)` | A | B / C / D | 拿用户画像 |
| `ws.emit_agent_xxx(...)` | A | B / C / D | 推 Agent 事件 |
| `metrics.calc_xxx(...)` | A | B / C / D | 3 项硬指标计算 |
| `auth_middleware.require_auth` | A（公共） | B / C / D | 鉴权 |
| `B04_get_student_snapshot(userId)` | B | D | 拿学生学情快照 |
| `B06_list_kb_chunks_by_kp(kp_id)` | B | C | 检索知识库 |
| `log_agent_event(...)` | D | B / C | 落 agent_log |
| `ai_service.chat_with_prompt(...)` | D | B / C | 调 AI |
| `audit(resource, cited_chunks)` | D | D 内部 / C | 审核资源 |
| `orchestrate(studentId, resource_type)` | D | A-05 | 端到端编排 |

**输出**：1 个具体的对外函数 + 字段定义

**验证**：
- [ ] 函数在对方区概览.md 中**明确声明**
- [ ] 字段名 / 类型 / 路径与声明**完全一致**

**失败处理**：声明没找到 → 群里问，**不要**自己假设

---

## 步骤 3：在自己区 import（按规范路径）

**输入**：步骤 2 的函数

**操作**：用**规范路径** import

**正确示例**：
```python
# A 区的对外函数
from backend.1_用户与聊天.user.service import get_user_by_id
from backend.1_用户与聊天.ws.emit import emit_agent_result
from backend.公共.metrics import calc_hallucination_rate
from backend.公共.auth_middleware import require_auth

# B 区的对外函数
from backend.2_学情数据.profile.service import get_student_snapshot
from backend.2_学情数据.kb.service import list_kb_chunks_by_kp

# D 区的对外函数
from backend.4_AI集成.services.ai_service import chat_with_prompt
from backend.4_AI集成.models.agent_log import log_agent_event
```

**错误示例**（**绝对禁止**）：
```python
# ❌ 不要直接 import 私有模块
from backend.2_学情数据.models import Activity  # 私有
from backend.1_用户与聊天.db import get_session  # 私有

# ❌ 不要 hardcode 对方的数据库 URL
DB_URL = "postgresql://user:pass@host:5432/user_chat_db"

# ❌ 不要复制对方代码到自己区
def get_user_by_id(userId):  # 复制 A 的代码
    ...
```

**输出**：规范的 import 语句

**验证**：
- [ ] import 的路径是对方**概览.md 中明确暴露的**
- [ ] 没有 import 私有模块
- [ ] 没有 hardcode 数据库连接

**失败处理**：路径不对 → 查对方区概览.md，**不要**自己探

---

## 步骤 4：调用对方函数（加 try/except）

**输入**：步骤 3 的 import

**操作**：
```python
def my_function(userId):
    try:
        user = get_user_by_id(userId)  # A 的对外函数
        if not user:
            raise UserNotFoundError(userId)
        return user
    except ConnectionError as e:
        log_error(f"调用 A 区失败: {e}")
        return None  # 或用默认值
    except Exception as e:
        log_error(f"未预期错误: {e}")
        raise
```

**关键点**：
- **必须**加 try/except（**不要**让对方的服务挂掉让自己也挂）
- fallback 行为要明确（None / 默认值 / 重试）
- 错误要 log

**输出**：1 个健壮的跨区调用

**验证**：
- [ ] 对方服务正常时 → 调用成功
- [ ] 对方服务挂掉时 → 自己的服务**不挂**
- [ ] 错误有 log

**失败处理**：fallback 不合理 → 群里讨论，**不要**静默吞错

## 步骤 5：加集成测试

**输入**：跨区调用代码

**操作**：`tests/test_cross_module.py`
```python
def test_b_can_call_a_user():
    """B 区能正确调用 A 区的 get_user_by_id"""
    from backend.2_学情数据.xxx import my_function
    with patch("backend.1_用户与聊天.user.service.get_user_by_id") as mock:
        mock.return_value = {"userId": "u1", "username": "test"}
        result = my_function("u1")
        assert result["userId"] == "u1"
```

**输出**：1 个集成测试

**验证**：
- [ ] pytest 全过
- [ ] mock 对方的失败 → 自己的 fallback 触发

## 步骤 6：协调变更

**输入**：跨区调用代码

**操作**：如果对对方的函数有修改需求：
1. **不要**直接改对方代码
2. 群里提需求，说明：
   - 我要用你的 XXX 函数
   - 我需要它返回 YYY 字段
   - 你方便改吗？
3. 对方同意后，**对方**改 + 升级版本号
4. 自己 import 新版本

**输出**：1 份协调记录（含双方同意）

**验证**：
- [ ] 变更在群里达成共识
- [ ] 对方已升级并部署
- [ ] 自己已切换到新版本

**失败处理**：对方拒绝 → 群里升级，**不要**硬上

## 跨区调用验收清单

- [ ] 步骤 1：确认真的需要跨区
- [ ] 步骤 2：找到对方区声明的对外函数
- [ ] 步骤 3：import 路径规范
- [ ] 步骤 4：调用有 try/except + fallback
- [ ] 步骤 5：集成测试覆盖
- [ ] 步骤 6：变更经过协调

**任何一步违反 = 跨区调用不合规 ❌**

---

## 常见错误清单（**AI 必看**）

| 错误 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 直连对方数据库 | 破坏数据库隔离 | 调对方对外函数 |
| import 对方私有模块 | 破坏模块边界 | 只 import 概览.md 声明的 |
| 复制对方代码 | 代码不同步 | 调对方函数 |
| 改对方代码不通知 | 制造冲突 | 群里提需求 |
| 自己实现"等价"函数 | 重复造轮子 | 调对方已有函数 |
| hardcode 数据库 URL | 破坏可移植性 | 从 config 读 |
