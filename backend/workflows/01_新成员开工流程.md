# 工作流程 01：新成员开工流程（**4 人通用**）

> **本流程 4 个成员都要走一遍**，从 `git pull` 到第一个任务开工。

---

## 前置条件

- 已安装 Python 3.10+ / Node.js 18+ / Git
- 已配置 GitHub 仓库权限
- 已克隆仓库到本地
- 已与队长确认自己是 A / B / C / D 哪个角色

---

## 步骤 1：拉取最新代码

**输入**：本地仓库路径

**操作**：
```bash
cd d:\TZB\TZB-XH202630
git checkout main
git pull origin main
```

**输出**：本地 main 分支已是最新

**验证**：
```bash
ls backend/
# 应该看到：公共/  a_用户与聊天/  b_学情数据/  c_学习内容/  d_AI集成/  prompts/  workflows/  任务清单_*.md
```

**失败处理**：
- 拉取冲突 → 群里 @队长，**不要** `git push --force`
- 目录缺失 → 重新 `git pull` 或问队长

---

## 步骤 2：检查自己的区目录是否就绪

**输入**：自己的角色（A / B / C / D）

**操作**：根据自己的角色确认目录存在
```bash
# A
ls backend/a_用户与聊天/

# B
ls backend/b_学情数据/

# C
ls backend/c_学习内容/

# D
ls backend/d_AI集成/
```

**输出**：看到自己区的目录 + `概览.md`

**验证**：每个区目录里至少有 `概览.md` + `db.py` + `config.py`（A 区还应有 `ws/`）

**失败处理**：目录里**只有 `概览.md`**，缺 `db.py` → 你的 00 任务还没人做，去群里问

---

## 步骤 3：阅读"必读 5 件套"

**输入**：无

**操作**：按以下顺序阅读（每份都要读完，不能跳）

1. [`backend/概览.md`](file:///d:/TZB/TZB-XH202630/backend/概览.md) — 分工总览
2. [`backend/协作协议.md`](file:///d:/TZB/TZB-XH202630/backend/协作协议.md) — 工作协议 + 3 项硬指标
3. `backend/任务清单_N_xxx.md`（N = 1/2/3/4，自己那份）— 具体任务
4. `backend/<N_xxx>/概览.md`（自己区目录里的）— 详细对外契约
5. `backend/prompts/0X_成员X_xxx_提示词.md`（X = 1/2/3/4）— AI 协作者提示词

**输出**：脑子里有了"我负责什么、不能碰什么、3 项硬指标是什么"的清晰认知

**验证**：能回答出以下 5 个问题
- [ ] 我是哪个成员？
- [ ] 我负责的目录是什么？
- [ ] 3 项硬指标的目标值是什么？
- [ ] 我的工作范围边界是什么（不能碰哪些文件）？
- [ ] 我的第一个任务 ID 是什么？

**失败处理**：任何一个问题答不上 → 重新读对应文档；不要凭印象猜

---

## 步骤 4：找到自己"当前应该做的任务"

**输入**：`backend/任务清单_N_xxx.md`

**操作**：
1. 打开自己那份任务清单
2. 找第一个状态为 ⬜ 待开始 或 🟡 进行中 的任务
3. 检查"依赖"列：依赖的任务是否全部 ✅
4. 如果依赖未完成 → 标 🔒 阻塞，群里问对应负责人
5. 如果依赖已完成 → 这是你当前任务

**输出**：1 个具体任务（含 ID、标题、涉及文件、验收标准）

**验证**：
- [ ] 任务状态已从 ⬜ 改为 🟡
- [ ] 已补 **Owner** 字段（写自己的名字 / 昵称）
- [ ] 已补 **Started** 字段（写当天日期）

**失败处理**：
- 找不到 ⬜ 任务 → 你的任务已全部完成，或在群里找新任务
- 任务依赖未完成 → 不要硬做，群里等

---

## 步骤 5：加载对应的"工作流程文档"

**输入**：当前任务 ID（如 `B-05`）

**操作**：查 `backend/workflows/README.md` 找到对应工作流程
- 例如：B-05 → `workflows/06_3大Agent开发流程.md`
- 例如：A-01 → `workflows/02_A区开发流程.md`
- 例如：B-06 → `workflows/09_知识库与画像流程.md`

**输出**：1 份"步骤式 checklist"工作流程

**验证**：工作流程文档的"前置条件"都已满足

**失败处理**：前置条件不满足 → 先做前置任务，**不要**跳步

---

## 步骤 6：按工作流程一步步执行

**输入**：工作流程文档

**操作**：严格按工作流程的"步骤 1 → 步骤 2 → ..."执行
- 每步做完"验证"才进下一步
- 遇到"失败处理"分支 → 按提示走
- **不**允许跳步或自由发挥

**输出**：任务完成（代码 + 测试 + 自检报告）

**验证**：工作流程最末"验收清单"全部勾选

---

## 步骤 7：提交与汇报

**输入**：本任务所有变更

**操作**：
1. 把自己区的 `任务清单_N_xxx.md` 中该任务状态改为 ✅
2. 勾选"验收标准"的所有 checkbox
3. `git add` 自己区目录 + 任务清单
4. `git commit -m "<任务ID> <简述>"`
5. 推到自己分支 + 群里汇报

**详细步骤**：[`workflows/14_Git提交与PR流程.md`](file:///d:/TZB/TZB-XH202630/backend/workflows/14_Git提交与PR流程.md)

**输出**：1 个 commit + 1 条群消息

**验证**：
- [ ] 任务状态已改为 ✅
- [ ] 验收 checkbox 全部勾选
- [ ] commit message 含任务 ID
- [ ] 群里已汇报

---
