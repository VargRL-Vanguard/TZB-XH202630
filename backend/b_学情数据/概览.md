# b_学情数据/ — 成员 B：学情数据 + **3 大 Agent 之学情诊断 Agent**

> **本项目参赛 XH-202630 挑战杯，目标擂主**。B 负责学情诊断 Agent + 垂直领域知识库切片 + ≥3 组差异化测试画像（**9-5 必交材料**）。

## 负责接口

- 学情画像：`/api/student/info`、`/api/student/metrics`、`/api/student/dimensions`、`/api/student/behavior`、`/api/student/knowledge`、`/api/student/suggestions`
- 学习活动：`/api/activity/stats`、`/api/activity/courses`、`/api/activity/recent`、`/api/activity/calendar`、`/api/activity/record`

## 3 大 Agent 之学情诊断 Agent（B-05 ⭐）

> **挑战杯 3 个核心 Agent 之一**（其他 2 个在 C-04 / D-06）。

**职责**：拿 `get_student_snapshot` 画像 + 历史活动 → 精准锚定强弱项 + 知识盲区。
**入口**：`backend.b_学情数据.analytics.diagnose(studentId) -> DiagnosisResult`
**输出**：`{weakKPs[], strongKPs[], knowledgeGaps[], confidence, traceId}`
**事件**：通过 A-04 `ws.emit(agentName="学情诊断Agent", ...)` 实时推送。

## 3 项硬指标责任

| 指标 | B 的贡献 |
| --- | --- |
| 幻觉率 | **B-06 知识库切片**质量直接决定后续生成内容的幻觉率 |
| 覆盖率 | **B-06 知识库切片**必须 ≥ 30 kp / 200 chunk / 覆盖率自检 ≥ 0.90 |
| 适配准确率 | （C 的责任，B 提供高质量画像输入） |

## 对外契约（**A/C/D 必看**）

> **重要**：以下函数均为 **async**，调用方需 `await`。

### get_student_snapshot
```python
from backend.b_学情数据.student import get_student_snapshot
snapshot = await get_student_snapshot("s001")
# 返回：{
#   "studentId", "name", "learnerProfile": {education, major, theoryTestScore, weakKPs[], strongKPs[]},
#   "metrics": {studyHours, completionRate, avgScore, trend, trendValue},
#   "dimensions": {comprehension, application, analysis, evaluation, creation, collaboration},
#   "knowledge": [{kp_id, kp_name, mastery, status}, ...],  # 6 个模块
#   "recentActivities": [...]  # 最近 7 天活动
# }
# 学生不存在返回 None
```

### get_recent_activities
```python
from backend.b_学情数据.activity import get_recent_activities
activities = await get_recent_activities("s001", days=7, limit=50)
# 返回：list[dict]，按时间倒序；无数据返回 []
```

### diagnose ⭐ 学情诊断 Agent
```python
from backend.b_学情数据.analytics import diagnose
result = await diagnose("s001")
# 返回：{
#   "studentId": "s001",
#   "weakKPs": ["kp12", "kp15"],
#   "strongKPs": ["kp03"],
#   "knowledgeGaps": [{"kp_id", "kp_name", "severity", "evidence"}],
#   "confidence": 0.82,  # [0,1]，<0.6 抛 QualityError
#   "traceId": "trace-dia-s001-...",
#   "generatedAt": "2026-08-13T10:00:00.000000"
# }
# 异常：NotFoundError（学生不存在）/ QualityError（confidence < 0.6）
```

### 知识库检索函数 ⭐

## B-08 自检脚本

> B-08 是 A-05 端到端验收前的**预演**：B 自己先跑一遍覆盖率 + 幻觉率两项硬指标，提前发现知识库缺口。脚本位于 `backend/b_学情数据/scripts/`。

### coverage_check.py — 核心知识点覆盖率自检

- **用途**：输入 3 组测试画像 + 知识库，统计 `kp_taxonomy.json` 中核心知识点被切片覆盖的比例，输出核心知识点覆盖率。
- **位置**：`backend/b_学情数据/scripts/coverage_check.py`
- **运行方式**：
  ```bash
  cd D:\TZB\TZB-XH202630
  python -m backend.b_学情数据.scripts.coverage_check
  ```
- **达标标准**：覆盖率 **≥ 0.90**；不达标立即迭代知识库（补充切片 / 扩充 kp）。
- **报告输出**：`docs/quality_reports/b_pre_check/coverage_report_{ts}.json`

### hallucination_check.py — 潜在幻觉率预估

- **用途**：输入 3 组测试画像 + 知识库，基于关键词匹配法预估知识库检索的潜在幻觉率（即诊断结果中无法在知识库找到支撑的知识点占比）。
- **位置**：`backend/b_学情数据/scripts/hallucination_check.py`
- **运行方式**：
  ```bash
  cd D:\TZB\TZB-XH202630
  python -m backend.b_学情数据.scripts.hallucination_check
  ```
- **达标标准**：幻觉率预估 **< 0.10**（A-05 端到端验收时再降到 < 0.05，留余量）。
- **报告输出**：`docs/quality_reports/b_pre_check/hallucination_report_{ts}.json`

### 报告归档

两个脚本运行后均将报告以 `report_{ts}.json`（`{ts}` 为时间戳）格式归档到 `docs/quality_reports/b_pre_check/` 目录，供 A-05 端到端验收时回溯比对。
