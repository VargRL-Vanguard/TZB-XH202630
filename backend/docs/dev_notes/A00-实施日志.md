## 遇到的问题

### 2026-08-11

#### 问题 1：目录名以数字开头导致 `invalid decimal literal`
- **现象**：`backend/1_用户与聊天/` 在 Python 看来像 `1_用户...` 数值字面量，相对导入 `from .1_xxx import ...` 报 `SyntaxError`。
- **解决方案**：把 `1_用户与聊天/` `2_学情数据/` `3_学习内容/` `4_AI集成/` 全部重命名为 `a_用户与聊天/` `b_学情数据/` `c_学习内容/` `d_AI集成/`，任务清单也对应从 `任务清单_1_xxx.md` 改为 `任务清单_a_xxx.md`。
- **影响面**：所有 prompt / workflow / 概览 / README 里的路径引用都得改，git 里看到的是"删除 + 新建"，实际只是重命名。

#### 问题 2：`.env` 文件编码成 latin-1
- **现象**：`UnicodeEncodeError: 'latin-1' codec can't encode characters` —— `.env` 里有中文占位符，pymysql 试图读 latin-1 失败。
- **解决方案**：用 PowerShell `Set-Content -Encoding utf8NoBOM` 重写 `.env`，密码占位符用纯 ASCII `L35714776`（用户真实密码）。`.env.example` 也保持纯 ASCII + 中文注释改英文。

#### 问题 3：外键约束失败（Cannot add or update a child row）
- **现象**：`seed_data.py` 里先 `session.add(profile)` 再 `session.add(user)`，SQLAlchemy 默认延迟 flush，commit 时 profile 的 user_id 外键找不到 user。
- **解决方案**：在 `session.add(user)` 之后立即 `await session.flush()` 强制 INSERT，让外键约束满足；profile 也 `await session.flush()` 一次。

#### 问题 4：`Event loop is closed` / `'NoneType' object has no attribute 'send'`
- **现象**：pytest-asyncio 每个测试用新事件循环，但 SQLAlchemy 默认连接池把连接绑定到**创建时**的事件循环，第二个测试开始时 loop 已关闭，连接失效。
- **解决方案**：
  1. `create_async_engine(..., poolclass=NullPool)` —— 不用池，每个请求开新连接，规避 loop 绑定问题。
  2. `pyproject.toml` 配 `asyncio_default_fixture_loop_scope = "session"`，所有测试共享同一个 loop。
  3. 移除 `pool_pre_ping=True`（NullPool 不需要）。

## 给 B/C/D 的避坑指南

1. **自己的数据放自己目录**：不要再搞"公共数据库"，每个区一个 schema（`user_chat_db` / `student_data_db` / `learning_content_db` / `ai_db`），通过 A/B/C/D 模块级函数跨区访问。
2. **pytest 异步测试必须用 NullPool** 或保持 `loop scope=session`，否则 `Event loop is closed` 必现。
3. **seed 数据先 `flush()` 再用外键**：SQLAlchemy 2.0 async 不会自动 flush，跨表依赖要手动 `await session.flush()`。
4. **环境变量全 ASCII**：`.env` 里所有值（特别是密码、URL）都必须是纯 ASCII，否则 pymysql 报 latin-1 错误。
5. **目录名别用数字开头**：Python 解析器把 `1_xxx` 当字面量，相对导入必失败。
