# ADR-0001：S-01 技术选型

**状态**：✅ 已采纳
**日期**：2026-08-11
**决策者**：A（成员 1）
**关联任务**：S-01 公共基础工具 + 评估指标计算器

---

## 背景

S-01 是项目第一个 P0 任务，需要为 4 个区（A/B/C/D）提供**跨区通用**的基础工具 + **3 项硬指标计算器**。选型直接影响：
- 后续 30+ 个任务的开发效率
- 演示视频的展示效果（FastAPI 自动生成 Swagger UI）
- 3 项硬指标的计算准确度（夺奖生死线）

---

## 备选方案

### 1. Web 框架

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **FastAPI** | 异步、原生 WebSocket、自动 OpenAPI 文档、类型提示友好 | 生态比 Flask 略新 |
| Flask | 生态最成熟、文档多 | 同步为主、WebSocket 要 flask-socketio |
| Quart | Flask 异步版、API 兼容 Flask | 文档少、坑多 |

### 2. 日志库

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **loguru** | 零配置、按模块命名、彩色输出 | 高级场景需要 hack |
| structlog | 结构化日志、生产级 | 配置复杂 |
| 标准 logging | 零依赖 | 配置样板代码多 |

### 3. 配置管理

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **pydantic-settings** | 类型安全、自动 .env 加载 | 多一层抽象 |
| python-dotenv | 轻量、简单 | 无类型检查 |
| 手动 dict | 完全可控 | 维护成本高 |

### 4. 3 项硬指标算法

#### 4.1 幻觉率

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **关键词匹配** | 快（< 5s）、零依赖 | 同义改写会漏报 |
| NLI 模型 | 准 | 要装 ~500MB 模型 |
| LLM 二次审核 | 最准 | 贵（每资源 1 次 API 调用） |

#### 4.2 画像-难度适配准确率

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **完全相等** | 严格、可解释 | 边界 case 难达标 |
| 差 ≤ 1 | 宽松 | 失去区分度 |

#### 4.3 核心知识点覆盖率

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **kp_tags 字段对比** | 快、准、依赖 C-04 已有字段 | 强依赖 schema |
| embedding 相似度 | 不依赖 schema | 慢、阈值难定 |
| 字符串包含 | 简单 | 同义词漏报 |

---

## 决策

| 维度 | 选型 |
| --- | --- |
| Web 框架 | **FastAPI** |
| 日志库 | **loguru** |
| 配置管理 | **pydantic-settings** |
| JWT 库 | **PyJWT** |
| 密码哈希 | **passlib[bcrypt]** |
| 幻觉率算法 | **关键词匹配**（切片去重后做"是否被 generated 引用"判断） |
| 准确率算法 | **完全相等** |
| 覆盖率算法 | **kp_tags 字段对比**（直接对比 generated.kp_coverage vs required_kps） |

---

## 后果

### 正面

- FastAPI 自动 OpenAPI → 演示视频能直接展示接口文档（用户体验加分）
- loguru 零配置 → 节省每个模块的样板代码
- 关键词匹配 + kp_tags 对比 → 3 项指标 < 5s 跑完，A-05 quality_check 不会卡

### 负面

- 关键词匹配可能漏报"近义词"幻觉（如把"工业机器人"改写成"工厂机械臂"）
- 完全相等的准确率可能在边界 case 上掉到 < 85%

### 缓解措施

- 关键词匹配：用**滑窗 + 同义词表**（B 知识库建设时维护 `synonyms.json`）
- 完全相等：在 B-07 测试画像里**只生成整数值**（1、2、3、4、5），避免浮点
- kp_tags：C-04 资源生成时**强制必填** kp_coverage 字段（D-06 审核会校验）
