# 后端工作协议

> 4 人 + AI 协作者共同遵守。修改本文档需 4 人评审。

## 1. 文档总览

```
backend/
├── 概览.md                          # 分工总览
├── 协作协议.md                       # 本文件：工作协议
├── AI协作指南.md                      # AI 协作者工作指南
├── 任务总看板.md                      # 跨区任务总看板（状态聚合）
├── 任务清单_1_用户与聊天.md              # ← 成员 1/A 唯一任务文档（含公共 S 任务）
├── 任务清单_2_学情数据.md               # ← 成员 2/B 唯一任务文档
├── 任务清单_3_学习内容.md               # ← 成员 3/C 唯一任务文档
├── 任务清单_4_AI集成.md                 # ← 成员 4/D 唯一任务文档
├── 公共/                            # 公共区（无 DB）
├── 1_用户与聊天/                      # A 区（含自有 db.py）
├── 2_学情数据/                       # B 区（含自有 db.py）
├── 3_学习内容/                       # C 区（含自有 db.py）
└── 4_AI集成/                        # D 区（含自有 db.py）
```

**所有人 / 所有 AI 必须先读 `协作协议.md` → `AI协作指南.md` → 自己专属的 `任务清单_N_xxx.md`**（每人只读自己那一个文件，里面已经包含公共 S 任务或本区全部任务）。

## 2. 任务 ID 规则

| 前缀 | 归属 | 示例 |
| --- | --- | --- |
| `S-xx` | 公共/ 公共任务 | `S-01` 公共基础（不含 db） |
| `A-xx` | 成员 A - `1_用户与聊天/` | `A-00` 本区数据层；`A-01` 用户认证 |
| `B-xx` | 成员 B - `2_学情数据/` | `B-00` 本区数据层；`B-01` 学情基础信息 |
| `C-xx` | 成员 C - `3_学习内容/` | `C-00` 本区数据层；`C-01` 路径概览 |
| `D-xx` | 成员 D - `4_AI集成/` | `D-00` 本区数据层 + AI 配置；`D-05` ChatAI 适配 |

子任务用 `A-03.1`、`A-03.2` … 编号。

## 3. 任务状态机

```
⬜ 待认领  ──►  🟡 进行中  ──►  ✅ 已完成
                  │
                  └────►  🔒 阻塞（备注原因）
```

- **认领**：把状态从 ⬜ 改为 🟡，并在任务后加 `**Owner**: @姓名` `**Started**: YYYY-MM-DD`
- **完成**：把状态改为 ✅，并勾选验收标准中的所有 `[ ]`
- **阻塞**：把状态改为 🔒，并在任务后加 `**Blocked by**: <原因>`
- **变更**：跨人修改他人任务时，**先在群里同步**，再改文档

## 4. 文件所有权红线

- 每人 / 每个 AI **只能**编辑自己区目录下的文件 + 根目录中自己专属的 `任务清单_N_xxx.md`
- `公共/` 只能由 A 编辑；A 改 `公共/` 前必须先 PR 并 @ B/C/D
- **数据库由各区自管**：自己区目录下可以新建 `db.py` / `config.py` / `models/`，**禁止**改他人区的这些文件
- 跨区调用一律走"对方暴露的模块级函数"或 `公共/` 公共接口，**禁止**直接读写他人数据表

## 5. 接口契约管理

每个对外接口的请求 / 响应字段以 `api-doc.js` 为准。任何人 / AI 修改字段时：

1. 同步更新 `api-doc.js` 中对应条目
2. 在自己专属的 `任务清单_N_xxx.md` 标注 `**契约变更**: 是 / 否`
3. 在群里通知可能受影响的人

## 6. Git 工作流

- 分支：`feat/<成员>-<任务号>-<简述>`，例 `feat/A-A03-login`
- 提交：`git commit -m "A-03 完成用户登录接口"`
- 合并：每天 18:00 由 A 汇总后合入 `main`，冲突由当事人当场解
- `git pull` 后第一件事：**打开根目录中自己专属的 `任务清单_N_xxx.md`，找到状态为 🟡 的任务继续**

## 7. 日常节奏

| 时间 | 动作 |
| --- | --- |
| 9:00  | git pull，更新自己专属的 `任务清单_N_xxx.md` 中任务的状态 |
| 12:00 | 在群里发一句进度（如 `A-03 完成 / A-04 进行中 / A-05 阻塞`） |
| 18:00 | 提 PR，汇总今日完成项 |
| 周末  | 同步下周任务优先级，调整自己专属 `任务清单_N_xxx.md` 中的 P0/P1/P2 |
