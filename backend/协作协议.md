# 后端工作协议

> 4 人 + AI 协作者共同遵守。修改本文档需 4 人评审。
> **本项目参赛 XH-202630 挑战杯，目标擂主（12 万）**。所有规则按**夺奖要求**加严，**任何人不得特例**。

## 0. 夺奖红线（**一票否决**，开工前必读）

### 0.1 3 项硬指标红线
提交作品（**2026-09-05**）前必须**全部**达标：

| 指标 | 目标值 | 验证方式 | 责任区 |
| --- | --- | --- | --- |
| 幻觉率 | **< 0.05** | A-05 `quality_check.py` 端到端跑通 | D 审核 Agent + B 知识库 |
| 画像-难度适配准确率 | **≥ 0.85** | A-05 `quality_check.py` 端到端跑通 | C 领域专家 Agent |
| 核心知识点覆盖率 | **≥ 0.90** | A-05 `quality_check.py` 端到端跑通 | B 知识库 + 诊断 |

**任一项不达标 → 禁止提交，立即进入迭代**（无任何例外）。指标函数实现在 `公共/metrics.py`，由 A 维护。

### 0.2 3 个核心 Agent 红线
- ✅ **学情诊断 Agent**（B-05）必须能跑通
- ✅ **领域专家 Agent**（C-04）必须能生成 3 种形态资源
- ✅ **审核裁判 Agent**（D-06）必须能输出 0-1 评分
- ✅ **协同编排器**（D-03）必须串起"分析-生成-校验-决策"闭环
- ✅ **辩论与交叉验证**机制必须实现（audit.score < 0.85 时触发）

**任一 Agent 缺位 / 闭环断裂 → 完整性 30 分全扣**。

### 0.3 9-5 必交材料红线
缺任一材料 → **直接失去参赛资格**：
- 源码 + 部署说明 + 单元测试
- ≥ 1 个垂直领域知识库切片（B-06）
- ≥ 3 组差异化学习者画像（B-07）
- ≤ 10 分钟演示视频（D-08）
- 15-20 页 PPT（D-09）

## 2. 任务 ID 规则

| 前缀 | 归属 | 示例 |
| --- | --- | --- |

| `A-xx` | 成员 A - `1_用户与聊天/` | `A-00` 本区数据层；`A-04` WebSocket；`A-05` 端到端验收 |
| `B-xx` | 成员 B - `2_学情数据/` | `B-00` 本区数据层；`B-05` 学情诊断 Agent；`B-06` 知识库；`B-07` 测试画像 |
| `C-xx` | 成员 C - `3_学习内容/` | `C-00` 本区数据层；`C-04` 领域专家 Agent；`C-05` 渲染器；`C-06` 动态迭代 |

夺奖专项任务用 `⭐` 标注（如 `B-06 ⭐ 夺奖专项`）。子任务用 `B-06.1`、`B-06.2` … 编号。

## 3. 任务状态机

```
⬜ 待认领  ──►  🟡 进行中  ──►  ✅ 已完成
                  │
                  └────►  🔒 阻塞（备注原因）
```

- **认领**：把状态从 ⬜ 改为 🟡，并在任务后加 `**Owner**: @姓名` `**Started**: YYYY-MM-DD`
- **完成**：把状态改为 ✅，并**勾选验收标准中的所有 `[ ]`**（不勾视为未完成）
- **阻塞**：把状态改为 🔒，并在任务后加 `**Blocked by**: <原因>`
- **变更**：跨人修改他人任务时，**先在群里同步**，再改文档
- **夺奖专项**（⭐）状态变更必须**在群里公告**

## 4. 文件所有权红线

- 每人 / 每个 AI **只能**编辑自己区目录下的文件 + 根目录中自己专属的 `任务清单_N_xxx.md`
- `公共/` 只能由 A 编辑；A 改 `公共/` 前必须先 PR 并 @ B/C/D
- **数据库由各区自管**：自己区目录下可以新建 `db.py` / `config.py` / `models/`，**禁止**改他人区的这些文件
- 跨区调用一律走"对方暴露的模块级函数"或 `公共/` 公共接口，**禁止**直接读写他人数据表
- **`docs/quality_reports/`** 是全员共享的 3 项指标报告目录，**任何人不允许删除/修改**他人写的报告

## 5. 接口契约管理

每个对外接口的请求 / 响应字段以 `api-doc.js` 为准。任何人 / AI 修改字段时：

1. 同步更新 `api-doc.js` 中对应条目
2. 在自己专属的 `任务清单_N_xxx.md` 标注 `**契约变更**: 是 / 否`
3. 在群里通知可能受影响的人
4. **夺奖相关接口**（`/api/visualization/*`、`/api/trace/*`、Agent 对外函数）变更需 4 人评审

## 6. Git 工作流

- 分支：`feat/<成员>-<任务号>-<简述>`，例 `feat/A-A03-login`
- 提交：`git commit -m "A-03 完成用户登录接口"`
- 合并：每天 18:00 由 A 汇总后合入 `main`，冲突由当事人当场解
- **8-22 起**：每日 22:00 前必须 push 当日进度到 main，**禁止**累积 2 天不提交
- `git pull` 后第一件事：**打开根目录中自己专属的 `任务清单_N_xxx.md`，找到状态为 🟡 的任务继续**
