# 10 排错急救手册（常见坑速查 · 全员）

> **用法**：卡住超过 30 分钟 → 先来这张表对症状 → 还不行 → 把「急救提示词」连同报错一起粘给你的 AI → 再不行 → 17:00 卡点上报。
> **原则**：禁止一个人闷头调试超过半天。80% 的联调 bug 是下面 12 类。

## 复制即用 · 急救提示词

```text
我在前端联调中遇到问题，请按以下流程帮我排错：
1. 先读 frontend/prompts/10_排错急救手册_常见坑速查.md，对照症状表给出最可能的 1-2 个原因和验证方法
2. 再读 frontend/prompts/08_接口契约速查表_字段级.md 核对我的请求/响应字段是否与契约一致
3. 给出最小化验证步骤（curl / 浏览器 DevTools Network 截图怎么看），先定位再动手改
4. 修复后列出这次踩的坑属于表中哪一类，我要汇总给队长

我的报错/现象：（粘贴报错原文、Network 截图描述、或复现步骤）
```

## 症状速查表

### A. 网络/接口类

| # | 症状 | 最可能原因 | 解法 |
| --- | --- | --- | --- |
| 1 | 浏览器控制台 CORS 报错 | 后端未放行 Vite 开发端口（5173） | 找 A 区加 CORSMiddleware allow_origins；**禁止**前端改用 proxy 掩盖后再不说 |
| 2 | 请求 401 但 token 明明刚拿到 | 请求头没带 `Authorization: Bearer `（注意 Bearer 后有空格）；或走了 mock 开关没走真实请求 | DevTools Network 看 Request Headers；检查 request.ts 拦截器是否统一注入 |
| 3 | 登录成功但刷新就掉线 | token 只存了内存变量，没进 sessionStorage | 统一走 auth store 的存储封装，禁止页面自己 localStorage.setItem |
| 4 | 401 死循环：跳登录页发的请求也 401 又触发跳转 | 响应拦截器对登录接口本身也做了 401 跳转 | request.ts 白名单：`/api/auth/login`、`/api/auth/register` 不触发跳转 |
| 5 | 返回 422 而不是 400 | FastAPI 校验失败默认 422，字段名/类型对不上契约 | 对照 08 号文档逐字段查：多了少了错了都会 422；studentId 传成 int 之类 |
| 6 | 拿到的 data 是 undefined | 后端返回 `{code,message,data}` 没解包，或 HTTP 状态 200 但业务 code≠200 | 拦截器统一解包；先 `console.log` 原始响应确认结构再删 |

### B. WebSocket 类

| # | 症状 | 最可能原因 | 解法 |
| --- | --- | --- | --- |
| 7 | WS 连上 60 秒就被踢 | 没发心跳，服务端超时清理 | 30s 定时 `{"type":"ping","timestamp":...}`；收到 pong 不用处理 |
| 8 | 重连风暴：断线后疯狂重连把后端打挂 | 退避没做或 setTimeout 叠加 | 指数退避 1/2/4/…30s 封顶；重连前 clearTimeout 上一个定时器 |
| 9 | 大屏收到事件但卡片不动 | 事件 `type` 判定用了 `===` 但后端发的是 `agent.start` 带引号差异 / store 没订阅 | 先 `console.debug` 原始 message 看真身；确认按 traceId 分组逻辑 |
| 10 | thinking 不流式，一次性全出来 | 用了 `content = 全文` 直接赋值 | 打字机按 30-50ms/字追加；新事件 push 进数组而非替换 |

### C. 构建/样式类

| # | 症状 | 最可能原因 | 解法 |
| --- | --- | --- | --- |
| 11 | ECharts 图表不显示或尺寸为 0 | 容器没高度 / tab 切换后没 resize | 容器显式 height；`chart.resize()` 挂 window resize + tab 切换钩子；离开页面 dispose |
| 12 | 深色大屏页面出现白色闪块 | 根元素背景没设，body 默认白 | 大屏路由根容器 + html/body 都设 `#0B1020`；路由切换前 meta 控制 |
| 13 | 打包后白屏，本地 dev 正常 | 路由用了 history 模式但 nginx 没配 fallback；或资源绝对路径 | vite base 相对路径 `./`；nginx `try_files $uri $uri/ /index.html` |
| 14 | 首屏 JS 超 500KB | ECharts / Element Plus 全量引入 | `echarts/core` 按需注册；unplugin 自动按需导入；路由懒加载 `() => import()` |

### D. 数据/逻辑类

| # | 症状 | 最可能原因 | 解法 |
| --- | --- | --- | --- |
| 15 | mock 切真实后字段全 undefined | mock 字段名与契约不一致（历史遗留写死） | 以 08 号文档为准逐字段改 mock，不是改请求侧 |
| 16 | 三画像切换图表不更新 | ECharts 数据是引用类型，setOption 没触发 | `chart.setOption(newOption, true)` 或 watch + nextTick |
| 17 | 内存的 demo 数据日期是 2026-07 | mock 日期写死，与当前周不符 | fixtures 日期用 `new Date()` 动态生成当前周 |

## 升级路径（对表也没解决时）

1. 17:00 卡点上报：症状 + 已排除的原因 + 最小复现步骤
2. @ 对应人：接口问题 @ 区负责人；基建问题 @ A；组件问题 @ F1
3. 队长判断是否触发 09 号应急预案的 No-Go 动作

> **给 AI 的强制指令**：排错时先对照本表和 08 号契约表定位，禁止不读契约就提议改字段名；修复后必须归类到上表某一条，若属于新坑，输出「症状/原因/解法」三行给我汇总进表。
