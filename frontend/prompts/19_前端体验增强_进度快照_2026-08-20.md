### 原始记录（留档）

### bug-1：Chat 页仍显示「服务暂不可用」黄条
- 现象：`/#/chat` 顶部 NetBanner 常驻「服务暂不可用，已展示缓存数据…」，且会话列表进错误态 → ChatQuickPanel 不渲染（1c 被阻塞）
- 实测：`GET /api/chat/list?userId=u001` 经 nginx **200**（带参修复生效）
- 排查方向：
  1. `src/api/request.ts` 的 `onNetStateChange`：失败置 true 后，**成功响应是否会回调 false**？（NetBanner 注释称"成功响应会持续触发 false 天然自愈"，但代理报告横幅常驻——疑似只有部分接口触发状态回调，或浏览器缓存旧 JS 未真正刷新）
  2. 让代理硬刷后 Network 面板确认加载的 JS hash 是否为最新版（此前 vite hash 文件名变了，但代理可能仍在旧页面）
  3. Chat.vue `loadConversations` 的 catch 是否因**其他请求**（如 WS 未连/别的接口）置错——错误态渲染条件是 `convError`
- 修好后必须补验：ChatQuickPanel 分页条 + emoji/短语插入（本轮 1c BLOCKED 项）

### bug-2：Ctrl+/ 快捷键面板不弹
- 现象：按 Ctrl+/ 与控制台 `dispatchEvent(new KeyboardEvent('keydown',{key:'/',ctrlKey:true}))` 均无反应
- 代码位置：`src/App.vue` onKeydown：`if (e.ctrlKey && e.key === '/')`
- 最可能原因：**中文输入法/键盘布局下 `e.key` 不是 `'/'`**（某些布局是 Shift 才出 /，或 IME 拦截）
- 修法：改判 `e.code === 'Slash'`（物理键位，不受布局/IME 影响）：
  ```ts
  if (e.ctrlKey && (e.key === '/' || e.code === 'Slash')) { ... }
  ```
