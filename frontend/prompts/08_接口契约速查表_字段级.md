> **用途**：联调前后逐字段核对的唯一依据；队长验收按 §8 DoD 逐条打勾。
> **来源**：`backend/a_用户与聊天/*/schemas.py`（A 区实测已上线）+ `api-doc.js`（B/C/D 契约）+ `ws/events.py`。
> **纪律**：实际返回与本文档不一致 → 群里 @ 责任人（auth/user/chat→A；student/activity→B；learning-path/suggestions→C；ai-chat/WS→D），**1 小时内响应，等待期间禁止自行猜字段改字段**。

## 0. 通用规范（所有接口一致）

| 项 | 值 |
| --- | --- |
| baseURL | `http://127.0.0.1:8000`（Swagger：`/docs`） |
| 统一响应 | `{ code: 200, message: "success", data: {...} }`，前端只取 `data` |
| 认证 | Header `Authorization: Bearer <token>`；token 有效期 24h |
| 分页 | `limit`（默认 20）+ `offset`（默认 0） |
| 测试账号 | student001 / student002 / teacher001 / admin001，密码统一 `Test@1234` |

**错误处理矩阵（全部接口统一，写进 request 封装一次搞定）：**

| code | 含义 | 前端行为（唯一标准） |
| --- | --- | --- |
| 200 | 成功 | 取 `data` 渲染 |
| 400 | 参数错误 | toast 显示后端 `message` 原文（后端已保证中文友好） |
| 401 | 未登录/token 过期 | 清 token + Pinia 用户态 → 跳 `/login`（WS 收 `error` 同样触发） |
| 403 | 无权限 | toast `message` |
| 404 | 资源不存在 | toast `message` 或空态页 |
| 500 | 服务器错误 | 统一 toast「服务异常，请稍后重试」，**禁止透出 detail/堆栈** |
| 网络失败/超时 | 断网/后端挂 | 全局黄色横幅「服务暂不可用」+ 已缓存数据照常展示 |

## 1. A 区：鉴权 / 用户 / 聊天（已上线，直接联调）

### 1.1 POST `/api/auth/register`

| 请求字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| username | string | 3-64，唯一 | 登录名 |
| password | string | 8-128 | 后端校验强度：≥8 位 + 字母 + 数字 |
| name | string | 1-64 | 显示名 |
| role | enum | student / teacher / admin | 下拉三选一 |
| education | string? | ≤32 | 学生可选 |
| major | string? | ≤64 | 学生可选 |

响应 `data`：`{ userId: string }`。重复注册 → 400「用户名已存在」。
**前端预校验**：密码 ≥8 位 + 含字母 + 含数字，不满足按钮置灰 + 具体原因（与后端双保险）。

### 1.2 POST `/api/auth/login`

请求：`{ username, password }` → `data: { token: string, userId: string, role: string }`
错误密码 → 401「用户名或密码错误」。
登录成功后端行为（前端必做）：token 存封装存储 + userId/role 入 Pinia + **按 role 跳转**（student→`/dashboard`；teacher→学生列表；admin→`/quality`）。

### 1.3 POST `/api/auth/logout`

无请求体 → `data: { ok: true }`。前端同时清本地 token/用户态再跳登录。

### 1.4 GET `/api/user/info?userId=u001` ⚠️ 必带 userId query

`data` 字段（User + LearnerProfile 合并）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| userId / username / name / role | string | 基础信息 |
| education | string? | 学历，无画像时为 null |
| major | string? | 专业 |
| theoryTestScore | int? | 0-100 |
| weakKPs / strongKPs | string[] | 弱/强知识点 ID 列表（画像编辑与仪表盘联动关键） |
| profileUpdatedAt | string? | ISO8601 |

### 1.5 PUT `/api/user/profile`

请求体（全部可选，**覆盖式更新**）：`{ education?, major?, theoryTestScore?(0-100), weakKPs?, strongKPs? }`
响应：同 1.4 结构（更新后回显）。
权限：学生只能改自己；带他人 `?userId=` → 403（前端不主动传他人 id）。

### 1.6 POST `/api/chat/send`

请求：`{ userId: string(=当前登录用户), targetId: string, content: string(1-2000), type: "text"|"image"|"file"(默认text) }`
响应：`{ id: int, timestamp: string(ISO), status: "sent"|"read" }`

### 1.7 GET `/api/chat/history?userId=&targetId=&limit=&offset=`

`data: { list: [{ id, userId, targetId, content, type, timestamp, status }], total: int, hasMore: bool }`
渲染规则：`userId === 当前用户` → 右侧气泡；否则左侧。`status==="read"` 显示 ✓✓。

### 1.8 GET `/api/chat/list`

`data: [{ targetId, name, lastMessage, lastTime, unread }]` —— 会话列表，`unread>0` 显示红色角标。

### 1.9 POST `/api/chat/read`

请求：`{ userId(当前用户), targetId }` → `data: { success: bool, markedCount: int }`。进入会话即调用。

## 5. WebSocket 协议（逐字段，D 区大屏 + A 区聊天共用）

**连接**：`ws://127.0.0.1:8000/ws?token=xxx`（已核对 `ws/server.py`：**只需 token**，用户身份从 JWT 解出；握手失败统一 close 4401）

### 5.1 客户端可发（4 类，字段名一字不差）

```json
{ "type": "ping", "timestamp": 1786783773 }
{ "type": "subscribe",   "channel": "agent:学情诊断Agent" }
{ "type": "unsubscribe", "channel": "agent:学情诊断Agent" }
{ "type": "chat", "targetId": "u002", "content": "你好" }
```

频道名格式：`agent:<agent_name>`，三个固定频道：`agent:学情诊断Agent` / `agent:领域专家Agent` / `agent:审核裁判Agent`。

### 5.2 服务端 5 类 Agent 事件（夺奖红线，逐字段）

| 事件 | 字段 | 前端 UI 行为（唯一标准） |
| --- | --- | --- |
| `agent.start` | `agentName, step(int), traceId, timestamp(float秒)` | 对应 AgentCard → running（呼吸灯/转圈）；进度条跳到 step |
| `agent.thinking` | `agentName, step, content(string), traceId, timestamp` | content **打字机流式追加**（30-50ms/字）到该卡片气泡区；逐条追加非整体替换 |
| `agent.result` | `agentName, step, content, data(dict), traceId, timestamp` | 卡片 → done ✅；`data` 暂存 Pinia agentEvents 待 final |
| `agent.debate` | `agents(string[]), topic, content?, traceId, timestamp` | 参与卡片间 ⚡ 连线；topic 居中；content 观点气泡左右交替 |
| `agent.final` | `ok(bool), summary, traceId, timestamp` | 全部 loading 关闭；ok=true 弹资源结果卡；ok=false 错误 + 重试按钮 |

事件典型顺序：`start → thinking×N → result → debate(可选) → final`。
**硬性容错**：乱序不白屏；气泡最多 50 条；未知 type 只 console.debug。

### 5.3 其他服务端推送

```json
{ "type": "message", "from": "u002", "content": "...", "timestamp": "..." }
{ "type": "notification", "title": "学习提醒", "content": "..." }
{ "type": "ai_reply", "content": "..." }
{ "type": "pong" }
{ "type": "error", "message": "..." }
```

心跳：30s 一次 ping；断线指数退避重连 1s/2s/4s…最大 30s；重连中顶部黄色横幅。

## 8. 每页 DoD（队长验收逐条打勾，可测才可签）

### Login（A）
- [ ] 输错密码 → **表单内联红字「用户名或密码错误」**，不跳页、不 alert、不发第二次请求
- [ ] 密码 <8 位或纯数字/纯字母 → 按钮置灰 + 具体原因文案
- [ ] 连点登录按钮只发 1 个请求（按钮 loading + disabled）
- [ ] student001 登录成功 → 跳 `/dashboard`；刷新页面仍登录（守卫放行）
- [ ] 回车可提交；首屏含项目名 + 副标题 + 渐变背景（截图当录屏第一画面）

### Register（A）
- [ ] 全字段提交成功 → toast「注册成功」→ 自动跳登录
- [ ] 重复用户名 → 400 toast「用户名已存在」（后端原文）
- [ ] role 下拉三选一；education/major 选填可空提交

### 路由守卫（A）
- [ ] 未登录直输 `/dashboard` URL → 弹回 `/login`
- [ ] token 过期后任意操作 → 401 → 清态跳登录（HTTP 与 WS 双通道）
- [ ] 乱输路径 → 中文 404 页 + 返回首页按钮
- [ ] 每个路由 `document.title` 为中文且切换跟随

### Chat（A）
