## 四、环境启停

```powershell
# 方式一：一键（推荐，自动开两个窗口分别跑后端/前端）
.\start_dev.ps1

# 方式二：手动两终端
.\venv\Scripts\python.exe -m backend.main    # 或 py -m backend.main（全局环境同样已装依赖）
cd frontend; npm run dev

# 方式三：Docker 一键容器化（mysql + backend + frontend 三容器，首次 build 约 3-5 分钟）
# ✅ 2026-08-19 已实测全绿：登录/A/B/C/D/quality 8 接口经 nginx 反代全 200，WS 反代升级收 connected
docker compose up -d --build
#   浏览器入口 http://127.0.0.1:8080 （nginx 同源反代 /api /ws，后端 8000 仅调试用）
#   停止：docker compose down ；彻底重置（含数据卷）：docker compose down -v
#   容器日志看种子灌入：docker logs tzb-backend

# 种子数据（幂等，可重复执行；换库/重置后必须重跑，否则页面空态）
py -m backend.a_用户与聊天.seed_data
py -m backend.b_学情数据.seed_data
py -m backend.c_学习内容.seed_data
```

- MySQL 库：`tzb_user_chat` / `tzb_student_data` / `tzb_ai_integration`（缺失时后端启动会报，建库后重跑 seed）
- AI Key 未配置 → AiChat 返回 503 + degraded，前端显示降级横幅，属预期非 bug
- Docker 注意：C 区同步引擎在容器里用 `mysql+pymysql` 方言（compose 已配好）；本地开发 C 区实际走 `learning_content.db`（sqlite 兜底，C 区 config 只读环境变量不读 .env），两者数据不互通属已知现状

### Docker 换机部署排坑（2026-08-19 本机实录，换机器先看这条）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| Win10 家庭中文版无 WSL2 | Docker Desktop 引擎起不来 | `winget install Microsoft.WSL`（提权）+ dism 启用 `Microsoft-Windows-Subsystem-Linux` 和 `VirtualMachinePlatform` 两个功能 + 重启。注意 `wsl --install` 若报 403 是系统代理拦了微软 CDN，走 winget 即可 |
| 国内拉不动 docker.io | build 时 `auth.docker.io` 连接超时 | 配镜像加速：`%USERPROFILE%\.docker\daemon.json` 加 `"registry-mirrors": ["https://docker.1ms.run", "https://docker.m.daocloud.io", "https://hub.rat.dev"]` 后重启 Docker Desktop（本机已配好） |
| Docker 相关文件清单 | — | `docker-compose.yml`（根）、`docker/backend.Dockerfile`、`docker/backend-entrypoint.sh`、`docker/mysql-init/01-databases.sql`、`frontend/nginx.conf`（须在 frontend context 内）、`.dockerignore` ×2 |
| 容器数据持久化 | — | MySQL 数据在 `tzb-mysql-data` 卷；`down` 不丢、`down -v` 全丢（重灌种子由 entrypoint 自动完成） |
